# ส่วนที่ 1 — วิธีการใช้งานเว็บไซต์ในแต่ละฟีเจอร์

## ฟีเจอร์ 01 — สมัครสมาชิก / เข้าสู่ระบบ / โปรไฟล์ผู้ใช้งาน
1. เปิดหน้า สมัครสมาชิก (`Register`) → กรอกชื่อ อีเมล และรหัสผ่าน
2. ระบบทำการลงทะเบียนผ่าน Supabase Auth และมี **Database Trigger (`on_auth_user_created`)** คอยสร้างแถวข้อมูลโปรไฟล์ลงตาราง `profiles` ให้อัตโนมัติทันที
3. ล็อกอินเข้าสู่ระบบ (`Login`) → แสดงชื่อผู้ใช้ และเปิดใช้งานการตั้งค่าการแจ้งเตือน Pop-up ประจำวัน (`is_notification_enabled = true`)

## ฟีเจอร์ 02 — เพิ่มและจัดการคลังฟิกเกอร์ (Add & Manage Figures)
1. กดปุ่ม **เพิ่มฟิกเกอร์ใหม่** (`/add`)
2. กรอกข้อมูลฟิกเกอร์: ชื่อฟิกเกอร์, ค่าย/ผู้ผลิต, ร้านค้าที่ซื้อ, ราคา (บาท), วันที่สั่งซื้อ/ได้รับ, สถานะสินค้า (`Pre-ordered` / `In Stock` / `Wishlist`), และสถานะการต่อ (`unbuilt` / `built`)
3. เลือก **หมวดหมู่ / เกรด** (ดึงรายการ Dynamic จากตาราง `categories` เช่น EG, HG, RG, MG, PG ฯลฯ)
4. อัปโหลดรูปภาพปก → ระบบบันทึกไฟล์ลง Supabase Storage Bucket (`figure-covers`) และดึง Public URL มาบันทึกเข้าตาราง `figure_items`

## ฟีเจอร์ 03 — Dashboard สรุปภาพรวมสถิติคลัง (Dashboard & Analytics)
1. เข้าสู่หน้าหลัก (`/`) ระบบประมวลผลคำนวณสถิติต่างๆ จากคลังฟิกเกอร์ของผู้ใช้งาน
2. แสดงการ์ดสถิติ 4 ด้าน: โมเดลทั้งหมด (ตัว), ต่อเสร็จแล้ว (ตัว), ยังไม่ได้ต่อ/งานดอง (ตัว), และมูลค่าคลังรวม (บาท)
3. แสดง Progress Bar คำนวณ % ความคืบหน้าการต่อโมเดลทั้งหมดในคลัง
4. แสดงตารางสรุปจำนวนโมเดลแยกตามหมวดหมู่แบบ Dynamic

## ฟีเจอร์ 04 — Quick Action เปลี่ยนสถานะต่อเสร็จแล้ว (Mark as Built)
1. ในหน้า Dashboard ส่วน **รายการค้างต่อล่าสุด**
2. เมื่อผู้ใช้ต่อโมเดลตัวไหนเสร็จ สามารถกดปุ่ม **"ต่อเสร็จแล้ว"** ทางขวามือของรายการนั้นได้ทันทีโดยไม่ต้องกดเข้าหน้าแก้ไข
3. ระบบทำการอัปเดตสถานะเป็น `built` และคำนวณสถิติ การ์ดสรุป และ % ความคืบหน้าบน Dashboard ใหม่ทันทีแบบ Real-time

## ฟีเจอร์ 05 — ระบบ Pop-up แจ้งเตือนงานดองประจำวัน (Daily Notification)
1. เมื่อผู้ใช้โหลดหน้า Dashboard ระบบจะตรวจสอบเงื่อนไข: ผู้ใช้เปิดรับการแจ้งเตือน (`is_notification_enabled = true`) และมีรายการโมเดลที่ยังไม่ได้ต่อ (`unbuilt`) อย่างน้อย 1 รายการ
2. ตรวจสอบความถี่การแสดงผลผ่าน `localStorage` (`figurecraft_last_popup_date`) หากยังไม่เคยแสดงผลในวันที่ปัจจุบัน ระบบจะเด้ง Pop-up สรุปรายการงานดองขึ้นมาวันละ 1 ครั้ง
3. บันทึกประวัติการส่งการแจ้งเตือนลงตาราง `notification_logs`

## ฟีเจอร์ 06 — บันทึกโน้ตการแต่งโมเดล (Custom Build Notes)
1. เปิดหน้ารายละเอียดฟิกเกอร์แต่ละรายการ
2. กรอกบันทึกเทคนิคงาน Custom เพิ่มเติม: โน้ตการเดินลาย (`detail_note`), โน้ตสูตรสีที่ใช้ (`paint_note`), และโน้ตการติดดีเค็ล (`decal_note`)
3. กดบันทึกข้อมูลเข้าตาราง `custom_build_notes` เพื่อเก็บเป็นบันทึกประวัติการต่อส่วนตัว

# ส่วนที่ 2 — โครงสร้าง Database ของเว็บไซต์ (ฟีเจอร์ไหนแตะตาราง/ฟิลด์ไหน)

## ฟีเจอร์ 01 : สมัครสมาชิก / เข้าสู่ระบบ / โปรไฟล์ผู้ใช้งาน
ใช้ตาราง `profiles` เป็นหลัก และเชื่อมโยงกับ Supabase Auth (`auth.users`)
| ตาราง/ฟิลด์ | ใช้ตรงไหน |
|---|---|
| `profiles.id` (FK → `auth.users.id`) | ผูกตัวตนผู้ใช้ระหว่างระบบ Auth กับโปรไฟล์ระบบ |
| `profiles.name` | ชื่อแสดงผลของผู้ใช้งาน |
| `profiles.notification_day`, `notification_time` | ตั้งค่าวันและเวลาสำหรับรอบแจ้งเตือน |
| `profiles.is_notification_enabled` | สวิตช์เปิด-ปิดการแสดง Pop-up แจ้งเตือนประจำวัน |
| `profiles.avatar_url` | รูปโปรไฟล์ผู้ใช้งาน |

## ฟีเจอร์ 02 : เพิ่มและจัดการคลังฟิกเกอร์
ตาราง `figure_items`, ตาราง `categories` และ Storage Bucket `figure-covers`
| ตาราง/ฟิลด์ | ใช้ตรงไหน |
|---|---|
| `figure_items(item_id, user_id, figure_name, purchase_date, merchant_name, manufacturer_name, status, price, assembly_status, created_at)` | ข้อมูลรายละเอียดของฟิกเกอร์แต่ละตัวในคลัง |
| `figure_items.cover_image` | เก็บ Public URL ของรูปภาพปก (+ ไฟล์ใน bucket `figure-covers`) |
| `figure_items.category_id` → `categories.id` | เชื่อมโยงหมวดหมู่/เกรดโมเดล |
| `categories(id, code, name, description)` | ตารางตัวเลือกหมวดหมู่ dynamic (เช่น HG, RG, MG) |

## ฟีเจอร์ 03 : Dashboard สรุปภาพรวมสถิติคลัง
อ่านข้อมูลจากตาราง `figure_items` และ `categories` มาประมวลผลคำนวณสถิติ
| ตาราง/ฟิลด์ | ใช้ตรงไหน |
|---|---|
| `figure_items.user_id` | กรองเฉพาะรายการฟิกเกอร์ของผู้ใช้ที่ล็อกอินอยู่ |
| `figure_items.assembly_status` | นับจำนวนที่ต่อแล้ว (`built`/`completed`) และยังไม่ได้ต่อ (`unbuilt`) เพื่อคำนวณ % ความคืบหน้า |
| `figure_items.price` | รวมราคาสินค้าคำนวณมูลค่ารวมของคลัง |
| `categories.name` | สรุปจำนวนโมเดลแยกตามชื่อหมวดหมู่ |

## ฟีเจอร์ 04 : Quick Action เปลี่ยนสถานะต่อเสร็จแล้ว (Mark as Built)
อัปเดตข้อมูลตาราง `figure_items`
| ตาราง/ฟิลด์ | ใช้ตรงไหน |
|---|---|
| `figure_items.assembly_status` | เปลี่ยนค่าจาก `'unbuilt'` เป็น `'built'` หรือ `'completed'` |

## ฟีเจอร์ 05 : ระบบ Pop-up แจ้งเตือนงานดองประจำวัน
ใช้ตาราง `profiles`, `figure_items` และ `notification_logs`
| ตาราง/ฟิลด์ | ใช้ตรงไหน |
|---|---|
| `profiles.is_notification_enabled` | เช็คสิทธิ์ว่าผู้ใช้เปิดรับการแจ้งเตือนหรือไม่ |
| `figure_items.assembly_status` | นับจำนวนรายการที่ยังไม่ได้ต่อ (`unbuilt`) มาแสดงใน Pop-up |
| `notification_logs(notification_id, user_id, scheduled_time, sent_at, delivery_status, unbuilt_count)` | บันทึกประวัติการแสดง Pop-up แจ้งเตือนงานดองของผู้ใช้ |

## ฟีเจอร์ 06 : บันทึกโน้ตการแต่งโมเดล (Custom Build Notes)
ใช้ตาราง `custom_build_notes` เชื่อมกับ `figure_items`
| ตาราง/ฟิลด์ | ใช้ตรงไหน |
|---|---|
| `custom_build_notes.item_id` → `figure_items.item_id` | ผูกโน้ตงาน Custom เข้ากับฟิกเกอร์ตัวที่กำหนด (1:1) |
| `custom_build_notes(detail_note, paint_note, decal_note, updated_at)` | บันทึกข้อความงานเดินลาย งานพ่นสี และงานติดดีเค็ล |
